**Rule**: a drafted plan/spec is a working hypothesis, not a contract.

**Why**: user observed that treating drafts as immutable produced over-engineered code when requirements drifted. Drafts should be ripped up freely when better information arrives.

**How to apply**: re-evaluate the plan whenever new constraints surface; don't anchor on what was written if it's clearly suboptimal now.
